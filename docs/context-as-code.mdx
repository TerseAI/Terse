`terse generate` compiles your connected integrations into a typed SDK. Your workflows reference real workspace resources instead of hardcoded IDs, and your coding agent (Cursor, Claude Code, Windsurf, etc.) gets full autocompletions and type safety when building automations.

## The problem

Without context-as-code, two things go wrong:

**At runtime**, your workflow rediscovers workspace context on every execution:

```ts
// Runtime discovery on every execution
const lists = await attio.lists.list()
const deals = lists.find(list => list.name === "New deals")

const channels = await slack.conversations.list()
const alertsChannel = channels.find(channel => channel.name === "deal-desk")

if (!deals || !alertsChannel) {
    throw new Error("Workspace context drifted")
}
```

This adds latency, wastes tokens, and breaks when names change.

**At build time**, your coding agent has no idea what resources exist in your workspace. It guesses at channel names, hallucinates list IDs, and produces workflows you have to manually fix. There is no autocomplete, no type checking, and no way for the agent to know what is actually available.

## The solution

`terse generate` solves both problems at once. It compiles your workspace context into typed code, so workflows never rediscover resources at runtime and coding agents build against real data from the start.

```ts
import { Terse, TerseAgent, Trigger } from "terse-sdk"

import { Apollo, Attio, AttioList, Slack, SlackChannel } from "./terse.generated"

const client = new Terse()

await client.createJob({
    name: "new-deal-enrichment",
    // This actually exists in the Attio Objects
    triggers: [Attio.onRecordCreated({ list: AttioList.Pipeline.NewDeals })],
    onTrigger: async (event: Trigger) => {
        const agent = TerseAgent.create({
            prompt: "You are reviewing a new CRM deal.",
            skills: [
                Attio.skill({ lists: [AttioList.Pipeline.NewDeals] }),
                Apollo.skill(),
                // This is a real slack channel in the workspace as well!
                Slack.skill({ channel: SlackChannel.DealDesk })
            ]
        })

        const enrichment = await agent.tools.apollo.enrichCompany({
            domain: event.record.values.company_domain
        })

        const prompt = [
            "You are reviewing a new CRM deal.",
            `Company: ${event.record.values.company_name}`,
            `Domain: ${event.record.values.company_domain}`,
            `Industry: ${enrichment.industry}`,
            `Employee count: ${enrichment.employeeCount}`,
            `Technologies: ${enrichment.technologies.join(", ")}`,
            "Return 3 bullets and one recommended next step."
        ].join("\n")

        const summary = await agent.runAndWait(prompt)

        await agent.tools.attio.updateRecord({
            list: AttioList.Pipeline.NewDeals,
            recordId: event.record.id,
            fields: {
                research_summary: summary
            }
        })
    }
})
```

## How it works

<Steps>
    <Step title="Connect integrations">Connect your CRM, enrichment provider, and messaging tools in the Terse app, or run `terse integrate`.</Step>
    <Step title="Run `terse generate`">Terse reads your connected integrations and their resources: lists, records, channels, owners, endpoints, and more.</Step>
    <Step title="The CLI writes `src/terse.generated.ts`">The generated file contains typed exports for triggers, skills, deterministic tools, and workspace constants specific to your account.</Step>
    <Step title="Your workflow imports those exports">You build against the generated types instead of runtime discovery. No name lookups. No hardcoded IDs. No drift.</Step>
</Steps>

## Benefits

- **Less runtime drift:** workspace structure is compiled into code.
- **Lower latency:** no API calls to discover lists, channels, or owners.
- **Type safety:** broken references fail at build time instead of in production.
- **Better prompts:** workflows start with real context, not guesses.
- **Coding agent friendly:** your agent gets autocompletions and typed outputs, so it builds correct workflows without you looking up IDs.
