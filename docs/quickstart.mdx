<Steps>
  <Step title="Install the CLI">

```bash
npm install -g terse-cli
```

  </Step>
  <Step title="Scaffold a project">

<CodeGroup>
```bash TypeScript
terse init my-project
```
</CodeGroup>

`terse init` handles the full setup in one command:

1. Authenticates first — reuses saved CLI credentials when they are still valid, or opens the browser for `terse auth login` when you are not signed in
2. Scaffolds your TypeScript project files (`src/terse.jobs.ts`, config, etc.)
3. Installs dependencies
4. Creates a Terse project and checks your connected integrations (prompts you to add more if needed)
5. Runs `terse generate` to produce a typed SDK from your workspace

If init fails after creating a new project directory, the CLI removes that directory so you are not left with a half-built folder on disk. To switch organizations or sign in as a different user, use `terse auth org switch` or `terse auth logout` followed by `terse auth login` — init does not prompt you to re-authenticate when you are already logged in.

After init, your project looks like this:

<CodeGroup>
```text TypeScript
my-project/
  src/
    index.ts              # your job definitions
    terse.generated.ts    # generated SDK (do not edit)
  package.json
  tsconfig.json
  .env.example            # copy to .env when you need project-level env vars
  .gitignore
```
</CodeGroup>

`terse auth login` during init stores CLI credentials in your **user config**, not in the project folder. Copy **`.env.example`** to **`.env`** when you want `TERSE_API_KEY` (or other secrets) available to your app or tooling as environment variables.

  </Step>
  <Step title="Write your workflow">

Open `src/index.ts` and define a job. The scaffolded file includes a starter example. Your generated SDK gives you typed helpers for every integration you connected: trigger builders, skill constructors, resource constants, and deterministic tool wrappers.

  </Step>
  <Step title="Test locally">

```bash
terse test
```

Runs your workflow locally against the Terse backend so you can verify it works before deploying.

  </Step>
  <Step title="Deploy">

```bash
terse deploy
```

Your code is packaged, uploaded, and hosted serverlessly. The CLI prints dashboard links (for example `https://app.useterse.ai/app/agents/...`) so you can open each workflow in the app. [Learn more about how deployment works.](/hosting)

  </Step>
</Steps>
