When you run `terse deploy`, your workflow goes from local code to a hosted, trigger-ready automation.

## What happens when you deploy

`terse deploy` packages your project and registers every job's triggers. Each run lands on an isolated [Modal](https://modal.com) sandbox provisioned per execution.

## Security

Each execution runs in its own isolated [Modal](https://modal.com) sandbox with a **project-scoped**, short-lived API token that is removed when the run finishes (and may also carry an expiration time). Your code and credentials are never shared across runs or organizations.

## What gets uploaded

The CLI respects standard ignore patterns. The following are always excluded:

<Tabs>
    <Tab title="TypeScript">`node_modules`, `.git`, `dist`, `.next`, `.turbo`, `.env`, `.DS_Store`</Tab>
</Tabs>

Everything else in your project directory is included in the deploy.
