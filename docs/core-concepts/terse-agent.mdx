`TerseAgent` is the runtime your handler uses to reason and act. It wraps the [OpenAI Agents SDK](https://openai.github.io/openai-agents-js/) under the hood, so you get the same agentic loop, tool-calling, and streaming model. On top of that, it adds the things workflows actually need: typed deterministic tool wrappers, structured outputs validated with `zod`, and access rules so the model only reaches integrations and resources you declared in **`skills`**—with extra checks on each model-driven tool call (see below).

You create one inside `onTrigger` with `TerseAgent.create()` and then either call tools deterministically, hand off to the model with `run()` / `runAndWait()`, or both.

<CodeGroup>

```ts TypeScript
import { TerseAgent, Trigger, createJob } from "terse-sdk"

import { Apollo, Attio, AttioList, Slack, SlackChannel } from "./terse.generated"

createJob({
    name: "score-new-deal",
    triggers: [Attio.onRecordCreated({ list: AttioList.Pipeline.NewDeals })],
    onTrigger: async (event: Trigger) => {
        const agent = TerseAgent.create({
            prompt: "You score new deals for ICP fit and notify the deal desk.",
            skills: [Attio.skill({ lists: [AttioList.Pipeline.NewDeals] }), Apollo.skill(), Slack.skill({ channel: SlackChannel.DealDesk })]
        })

        const summary = await agent.runAndWait("Score this account and explain why.")
    }
})
```

</CodeGroup>

## Agentic loop

`run()` and `runAndWait()` execute a full agentic loop on top of the OpenAI Agents SDK: the model picks a tool, the SDK executes it, the result is fed back, and the loop continues until the model produces a final answer. Every step is recorded in [Activity](/core-concepts/activity-and-observability) so you can replay the conversation later.

| Method                        | Returns                  | Use when                                               |
| ----------------------------- | ------------------------ | ------------------------------------------------------ |
| `run(message)`                | Async iterable of events | You want to stream progress (text deltas, tool calls)  |
| `runAndWait(message)`         | Final string             | You want the final text once the loop completes        |
| `runAndWait(message, schema)` | Validated typed object   | You want structured, schema-validated JSON (see below) |

The model only sees the tools you grant through the agent's `skills`. Everything else is invisible to it: your environment variables, your other integrations, and your other workflows.

## Structured outputs

Pass a `zod` schema as the second argument to `runAndWait` and the SDK forwards it to the model, parses the final JSON, and validates it before returning. The result is fully typed.

<CodeGroup>

```ts TypeScript
import { z } from "zod"

const ScoreSchema = z.object({
    score: z.number().min(0).max(100),
    rationale: z.string(),
    nextAction: z.enum(["accept", "review", "reject"])
})

const scored = await agent.runAndWait("Score this account and explain why.", ScoreSchema)

// scored is typed as: { score: number; rationale: string; nextAction: "accept" | "review" | "reject" }
if (scored.nextAction === "accept") {
    await agent.tools.attio.updateRecord({
        list: AttioList.Pipeline.NewDeals,
        recordId: event.record.id,
        fields: { fit_score: scored.score, scoring_notes: scored.rationale }
    })
}
```

</CodeGroup>

If the model returns malformed JSON or fails schema validation, the run errors out and is recorded as **Failed** in Activity, with no half-applied side effects to your CRM.

## Access control on model tool calls

The most important property of `TerseAgent` is what it _won't_ do. Even though the underlying OpenAI Agents SDK can call arbitrary tools, the Terse runtime constrains **model-driven** tool calls during **`run()`** and **`runAndWait()`** in two layers:

- **Which tools exist for the model:** The model only receives tools for integrations you declare in **`skills`**. If Slack is not in **`skills`**, the model cannot call Slack tools, even when Slack is connected for other code paths.
- **Whether a specific call is allowed:** Before the backend calls a third-party API, it validates the tool arguments against your connected configuration for that run—such as allowed Slack channels, GitHub repositories, Attio lists, Notion pages or databases, Linear teams or projects, Datadog indexes, PostHog projects, and valid `integrationId` values. Arguments outside the scopes implied by your **`skills`** are rejected; those failures show up as tool errors in [Activity](/core-concepts/activity-and-observability).

Skill configuration is how you declare those scopes—for example `Attio.skill({ lists: [AttioList.Pipeline.NewDeals] })`, `Slack.skill({ channel: SlackChannel.DealDesk })`, or `GitHub.skill({ repos: [...] })`.

Tools listed in **`toolApprovals`** are paused for [human approval](/core-concepts/human-in-the-loop) before execution.

Generated **`agent.tools.*`** only exposes integrations that appear in your **`skills`** array; use **`toolbox.*`** from `terse.generated.ts` when your handler code needs a connected integration you did not pass to **`TerseAgent.create()`**. Your code is responsible for passing the parameters you intend on deterministic paths.

<CodeGroup>

```ts TypeScript
const agent = TerseAgent.create({
    prompt: "You enrich and route inbound deals.",
    skills: [
        Attio.skill({ lists: [AttioList.Pipeline.NewDeals] }), // NewDeals only
        Apollo.skill(),
        Slack.skill({ channel: SlackChannel.DealDesk }) // DealDesk only
    ],
    toolApprovals: ["attio.updateRecord"] // human-in-the-loop on writes
})
```

</CodeGroup>

If you want the model to reach more, you have to grant more, explicitly and in code, where it shows up in code review and in the generated audit trail.
