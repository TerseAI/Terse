An actor stores shared state for one project, class name, and ID. Calls to the same actor run one at a time. Use workflow `states` for workflow-local values and actors for shared read-modify-write operations.

## Define and call an actor

Export named classes from `src/durable-objects.ts`:

```ts
import { Actor } from "terse-sdk"

export class AccountCounter extends Actor {
    count = 0

    async increment(): Promise<number> {
        return ++this.count
    }
}
```

Call `AccountCounter.get(accountId).increment()` from a workflow. Use a stable ID: changing the class name or ID addresses different state.

Classes must extend `Actor` directly, take no constructor arguments, and expose async methods. Keep arguments, results, and instance fields as plain JSON values. Export only actor classes from the entrypoint. Names and IDs may contain letters, digits, `.`, `_`, and `-`; `this.id` returns the current actor ID.

Successful calls persist enumerable fields; thrown errors discard state changes. Existing snapshots replace field initializers, so handle newly added fields with defaults such as `this.limit ?? 10`. Actor-to-actor calls are not supported.

## Durable workflows

Actor calls are not automatically journaled. In a `durable: true` workflow, call through a module-scope helper wrapped in `step()`:

```ts
import { createJob, step } from "terse-sdk"

import { AccountCounter } from "../durable-objects"
import { Triggers } from "../terse.generated"

createJob({
    name: "count-account-events",
    durable: true,
    triggers: [Triggers.webhook.onRequest<{ accountId: string }>()],
    onTrigger: async event => {
        await step(incrementAccount(event.body.accountId))
    }
})

async function incrementAccount(accountId: string): Promise<number> {
    return AccountCounter.get(accountId).increment()
}
```

The transform rejects `step(AccountCounter.get(id).increment())`; use the helper above.

`ActorInvocationError` exposes `code` and `requestId`. For `outcome_unknown`, the mutation may have committed. Read state to reconcile, or deduplicate with a stable operation ID; do not blindly retry.

## WebSockets

Actor hooks `onConnect`, `onMessage`, and `onClose` share the same serialized state as ordinary methods. Use `socket.send()` to reply and `this.broadcast()` to publish to connected clients. Connections receive an initial `state` event.

To start a workflow for each socket message, add a trigger using your actor class:

```ts
import { createJob } from "terse-sdk"

import { AccountCounter } from "../durable-objects"
import { Triggers } from "../terse.generated"

createJob({
    name: "count-socket-messages",
    triggers: [Triggers.durableObject.onMessage({ actor: AccountCounter })],
    onTrigger: async event => {
        await AccountCounter.get(event.actorId).increment()
    }
})
```

After deployment, the workflow details show a socket URL with an `{actorId}` placeholder and a socket key. Trusted servers send the key as a Bearer token during the WebSocket upgrade.

For browsers, your backend obtains a short-lived ticket using its project API token:

```http
POST /durable-objects/socket-tickets
Authorization: Bearer terse_project_token
Content-Type: application/json

{"triggerId":"trigger-id","actorId":"account-123","metadata":{"userId":"user-123"}}
```

Connect with `new WebSocket(ticket.url, ticket.protocols)`. Authenticate the user and authorize the actor ID in your backend before requesting a ticket; never expose the project API token or socket key to browsers. Actor hooks receive ticket metadata as `socket.metadata`.

## Deploy and test

Terse injects actor credentials automatically. Deploy actor changes before testing: actor hosts load definitions from the latest successful deployment, not your local files.

```bash
pnpm exec tsc --noEmit
terse deploy
terse test run "<workflow-name>" --id <sample-id>
```

Tests use a separate `test.<projectId>` namespace and do not change production actor state.

For a custom runtime, set `DURABLE_OBJECT_TOKEN`, `DURABLE_OBJECT_NAMESPACE_ID`, and `DURABLE_OBJECT_CONTROL_PLANE_URL` before the first actor call. Set `DURABLE_OBJECT_SOCKET_GATEWAY_URL` when the gateway is separate. Use a workflow token, never an admin token.

<Note>The `create-terse` self-hosted stack does not include the actor control plane.</Note>
