Skills define what integrations your workflow can interact with. Each skill exposes a set of tools that the agent can call (via agentic loops) or that you can call deterministically (via `agent.tools.*`).

In TypeScript, `terse generate` writes a single `Skills` object in `src/terse.generated.ts`. Import it and call the nested factory for the integration you want (for example `Skills.github({ repos: [...] })`). Built-in capabilities like `Skills.web()`, `Skills.imageEdit()`, and `Skills.memory()` are documented in their sections below.

## Meta Ads

Read ad performance, create and retire ads, sync custom audiences, and send offline conversions via the Conversions API.

```ts
import { MetaAdsAdAccount, Skills } from "./terse.generated"

skills: [Skills.metaAds({ adAccount: MetaAdsAdAccount.Primary, pageId: "1234567890" })]
```

### Scoping an automation to one ad account

`adAccountId` is required on every tool that takes one, so a call always says out loud which account it touches. Use the generated `MetaAdsAdAccount` values rather than raw strings.

`Skills.metaAds({ adAccount, pageId })` restricts what that automation's agent may touch: a tool call naming a different ad account or Page is denied. Omit both and the agent may use anything the connected login can reach.

| Tool                             | Description                                                            | Access |
| -------------------------------- | ---------------------------------------------------------------------- | ------ |
| `meta_ads_list_ad_accounts`      | List the ad accounts the connected login can reach                     | Read   |
| `meta_ads_list_campaigns`        | List campaigns with status, objective, and budget                      | Read   |
| `meta_ads_list_adsets`           | List ad sets, optionally narrowed to one campaign                      | Read   |
| `meta_ads_list_ads`              | List ads with the creative attached to each one                        | Read   |
| `meta_ads_list_audiences`        | List custom audiences with approximate sizes                           | Read   |
| `meta_ads_list_pixels`           | List pixels (Conversions API dataset IDs) in an ad account             | Read   |
| `meta_ads_list_pages`            | List the Facebook Pages the connected user manages                     | Read   |
| `meta_ads_read_insights`         | Spend, impressions, clicks, and conversions at campaign/ad set/ad level | Read   |
| `meta_ads_add_audience_users`    | Add people to a custom audience (emails/phones hashed)                 | Write  |
| `meta_ads_remove_audience_users` | Remove people from a custom audience (emails/phones hashed)            | Write  |
| `meta_ads_send_conversions`      | Send offline conversion events via the Conversions API                 | Write  |
| `meta_ads_create_ad`             | Create an ad: single image, single video, carousel, or dynamic creative | Write  |
| `meta_ads_set_status`            | Pause or resume a campaign, ad set, or ad                              | Write  |

Every list tool returns its own collection, a `count`, and `truncated`. There is one function per object type, so a result never carries optional arrays you have to narrow:

```ts
const adAccountId = MetaAdsAdAccount.Primary.accountId

const { campaigns } = await toolbox.metaAds.listCampaigns({ adAccountId })
const { adsets } = await toolbox.metaAds.listAdSets({ adAccountId, campaignId: campaigns[0].id })
```

### Judging and improving creative

Use `meta_ads_read_insights` with `level: "ad"` to attribute spend and results to an individual creative, optionally split by `breakdowns` such as `age` or `publisher_platform`. Campaign-level rows cannot tell one creative from another.

Meta does not allow a creative to be edited, and an ad's creative cannot be swapped for a different one. Improving a creative therefore means creating a **new** ad in the same ad set and pausing the old one:

```ts
const created = await agent.run("Create the approved variant and retire the loser")
// meta_ads_create_ad  -> new creative + new ad (PAUSED by default)
// meta_ads_set_status -> pause the ad that underperformed
```

This is also the better outcome: insights are keyed by ad id, so a new ad keeps the losing ad's history intact instead of overwriting it.

### Creative formats

`meta_ads_create_ad` takes a `creative` object discriminated by `format`, so only the fields that belong to the chosen format are in scope and both TypeScript and the model narrow to exactly one shape.

| `format`          | Media                                 | Text                                           | Meta `ad_format`   |
| ----------------- | ------------------------------------- | ---------------------------------------------- | ------------------ |
| `single_image`    | `imageUrl`                            | `message`, `headline?`, `description?`         | —                  |
| `single_video`    | `videoUrl`, `thumbnailUrl?`           | `message`, `headline?`, `description?`         | —                  |
| `carousel`        | 2-10 `cards`, each image **xor** video | `message` + per-card `headline`                | —                  |
| `dynamic_image`   | `imageUrls[]` (1-10)                  | `messages[]`, `headlines[]`, `descriptions[]?` | `SINGLE_IMAGE`     |
| `dynamic_video`   | `videoUrls[]` (1-10)                  | `messages[]`, `headlines[]`, `descriptions[]?` | `SINGLE_VIDEO`     |
| `dynamic_mixed`   | `imageUrls[]` + `videoUrls[]`         | `messages[]`, `headlines[]`, `descriptions[]?` | `AUTOMATIC_FORMAT` |

Each carousel card is itself discriminated, on `media`:

```ts
cards: [
    { media: "image", imageUrl, headline, description?, linkUrl? },
    { media: "video", videoUrl, headline, description?, linkUrl? }
]
```

Meta does not support video cards on Instagram placements, so a carousel containing one is Facebook-only.

Meta allows exactly one `ad_format` per asset feed, which is why the dynamic formats are three separate variants rather than one variant with two optional media arrays: the media kind determines the `ad_format`, so it cannot be optional. Dynamic creative is also capped at **30 assets in total** across media and text variants (the `ad_format` and `link_url` each count as one), enforced before anything is uploaded.

Shared across formats: `linkUrl`, `callToAction`, `instagramActorId`, `urlTags`, `status`.

Terse sends Meta only the fields you supply. Omit `callToAction` and no `call_to_action` is sent, so Meta renders its own default button; omit `showEndCard` and no `multi_share_end_card` is sent. The one exception is `status`, which defaults to `PAUSED` rather than Meta's `ACTIVE`, so a generated ad never starts spending without someone turning it on. The dynamic formats require `callToActions` because Meta rejects an asset feed with no `call_to_action_types`.

Images are fetched by Meta from the URL you supply. Videos are uploaded to the ad account and polled until Meta finishes encoding, and dynamic-creative images are uploaded to obtain the hash `asset_feed_spec` requires — so short-lived signed URLs are fine everywhere, including the ones `higgsfield_generate_image` and `higgsfield_generate_video` return. The result reports `videoIds` and `imageHashes` for whatever was uploaded.

`dynamic` only works on an ad set that already has dynamic creative enabled, and Terse has no ad-set write tools, so that setup happens in Ads Manager. When in doubt, ship separate single-format ads and compare them on ad-level insights instead.

New ads enter `PENDING_REVIEW` before reaching the status you requested, and can come back `DISAPPROVED`. Re-read `effective_status` with `meta_ads_list_ads` before treating an ad as live.

`meta_ads_set_status` only pauses and resumes. There is deliberately no budget tool, so an automation cannot increase spend on its own.

`meta_ads_read_insights` follows Graph API pagination up to 2000 rows and sets `truncated: true` in the result when more rows exist; narrow the date range or filter by campaign/ad set/ad IDs to fetch the remainder. Note that each breakdown multiplies the row count.

### Access and rate limits

Meta grants every app Standard Access automatically, which covers every tool above for users who have a role (Admin, Developer, or Tester) on your Meta app. No App Review is needed for that case. Reaching ad accounts belonging to users outside your app requires Advanced Access, App Review, and Business Verification.

Standard Access also carries lower rate limits, shared across everyone using your app: roughly `300 + 40 x active ads` calls per hour for management and `600 + 400 x active ads` for insights.

## Higgsfield

Generate ad creative images from a text prompt, then animate them into video.

```ts
import { Skills } from "./terse.generated"

skills: [Skills.higgsfield()]
```

| Tool                        | Description                                                  | Access |
| --------------------------- | ------------------------------------------------------------ | ------ |
| `higgsfield_generate_image` | Generate one or four images from a text prompt                | Write  |
| `higgsfield_generate_video` | Animate a still image into a video                            | Write  |
| `higgsfield_list_motions`   | List motion presets with their IDs, for `motionId`            | Read   |

Generation is asynchronous and the tools wait for it to finish, so a call can take a while. Each asset is copied into Terse-managed storage and returned as a signed URL valid for 24 hours. That URL can be shown to a human for approval and passed straight to `meta_ads_create_ad` as an `imageUrl` or `videoUrl`.

Every call spends Higgsfield credits, so both generators are marked as writes and can be gated behind approval. Use `batchSize: 4` when you want variants to compare, and match `size` to the placement: a landscape size such as `2048x1152` for feed ads, a portrait size such as `1152x2048` for stories.

### Video is image-to-video

Higgsfield animates an existing still; there is no text-to-video path. So a video ad is always two calls:

```ts
const { images } = await toolbox.higgsfield.generateImage({
    prompt: "A coffee tin on concrete, soft daylight, editorial styling",
    size: "1152x2048"
})
const { videos } = await toolbox.higgsfield.generateVideo({
    imageUrl: images[0].url,
    prompt: "Slow push in, steam rising, shallow depth of field",
    model: "dop-turbo"
})
```

`model` picks cost against quality: `dop-lite`, `dop-turbo` (default), `dop-standard`. Pass a `motionId` from `higgsfield_list_motions` to apply a named camera move on top of the prompt, with `motionStrength` between 0 and 1.

### Getting credentials

Higgsfield uses a key pair rather than OAuth, so there is no browser consent step. You paste the credentials once and Terse stores them as a write-only secret.

1. Sign in at [cloud.higgsfield.ai](https://cloud.higgsfield.ai) with email, Google, Apple, or Microsoft. This is the dashboard. `platform.higgsfield.ai` is the API endpoint itself and has no sign-up page, so do not go there looking for keys.
2. Open the API keys section of the dashboard and generate a new key.
3. Higgsfield issues **two** values: a **Key ID** and a **Key Secret**. Copy both before you leave the page.
4. Make sure the account has credits. Every generation spends them, and an empty balance fails the call rather than returning a lower-quality image.

Then connect it. The two values go in as a **single colon-joined string**, `KEY_ID:KEY_SECRET`, with no spaces, no quotes, and without the literal word `Key` that appears in Higgsfield's own `Authorization: Key ...` header examples. Terse splits on the colon and sends each half as the API expects.

In the console, open the Higgsfield card and paste it into the one field.

From the CLI, pass it on stdin rather than as a flag so the secret never reaches your shell history or the process list:

```bash
terse integrate connect higgsfield --fields-stdin <<<'{"credentials":"KEY_ID:KEY_SECRET"}'
```

`terse integrate describe higgsfield --json` prints the expected field, and `terse integrate disconnect higgsfield` removes the stored credentials.

Terse validates the pair immediately by making one authenticated read against Higgsfield, so a bad paste is rejected at connect time with the reason, rather than surfacing later as a failed job.

<Note>
    The Key Secret is a credential with spend attached: anyone holding it can burn your Higgsfield credits. Terse stores it write-only, meaning no API, tool, or agent can read it back after it is saved. Rotate it in the Higgsfield dashboard and reconnect if you suspect it leaked.
</Note>

- Query-grouped results omit anonymized queries, so their clicks will not sum to the property total.
- Submitting a sitemap only queues it. Check the outcome later with `google_search_console_get_sitemap`.

## Memory (built-in)

Gives a job a persistent `/memories` directory it can read and write across runs. With the skill added, the agent checks `/memories` before starting and records progress, context, and learnings as it works, so later runs pick up where earlier ones left off.

```ts
skills: [Skills.memory()]
```

| Tool     | Description                                                                                                             | Access |
| -------- | ----------------------------------------------------------------------------------------------------------------------- | ------ |
| `memory` | Read, write, edit, and organize files under `/memories` (`view`, `create`, `str_replace`, `insert`, `delete`, `rename`) | Write  |

### What persists between runs

Only files under `/memories` carry over. Every run otherwise starts fresh from your deployed code, so anything written elsewhere in the run is discarded. Anything the agent saves to `/memories` is still there on the next run.

### How memory is organized

- **Per project** — each project has its own isolated memory. Jobs in different projects never share memory.
- **Per job** — within a project, every job gets its own private space; one job cannot see another job's memory.
- **Scoped to `/memories`** — all paths stay inside the `/memories` directory.

Cleanup is automatic: deleting a job removes that job's memory, and deleting a project removes all memory for the project.

`terse test` runs against a separate, isolated test memory, so local testing never touches what your deployed job has saved.

### Inspecting memory

Use the [`terse memory`](/reference/cli#memory) commands to list, read, write, and delete a job's memory files from the terminal. Add `--test` to any of them to target the isolated `terse test` memory instead of production.
